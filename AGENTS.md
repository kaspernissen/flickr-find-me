# AGENTS.md

A CLI that scans a public Flickr album for photos of a person and downloads the
originals. Python 3.11, managed with uv. It ships as a Docker image on ghcr.io.

## Commands

```sh
uv sync                               # install
uv run pytest                         # fast tests, no network or model (default)
uv run pytest -m "network or model"   # hits Flickr / loads the ~280 MB face model
uv run flickr-find-me <album-url> me.jpg --limit 20   # quick real run (--limit is hidden)
docker build -t flickr-find-me:dev .
```

Write the failing test first. Every change needs a test, and the fast suite must
stay green and offline.

## Layout

`src/flickr_find_me/`, one responsibility per file:

- `flickr.py`: album URL parsing and the gallery-dl subprocess (listing, original URLs)
- `download.py`: HTTP client, retries, size cap, atomic `.part` writes
- `faces.py`: InsightFace wrapper (detect, reference embedding)
- `cache.py`: SQLite cache of photos, face embeddings and metadata
- `match.py`: scoring and match/maybe classification
- `report.py`: static `results.html`
- `cli.py`: arguments, orchestration, progress bar, summary

## Rules

- **Faces stay local.** No cloud APIs, and no uploads of user photos or embeddings.
- **No Flickr API key.** All Flickr metadata goes through gallery-dl, which gets
  Flickr's public key itself. We download images ourselves with httpx.
- **Validate input early.** Check everything before the network or the model:
  the album URL is parsed strictly (`parse_album_url`), reference images must
  exist, and flags are bounded. A bad input exits with code 2 and a one-line message.
- **One bad photo must not stop a run.** Per-photo failures mark the photo
  `failed`, and the next run retries it. Never mark a photo `done` unless its
  faces were saved.
- **Re-runs must not re-download.** Every scanned photo's face embeddings are
  cached, so new thresholds or new reference photos only re-score.
- **Keep the output short.** One progress bar and a summary. Library noise is
  suppressed, and failures are counted and reported once at the end.
- The code is generic to any public album. Don't hardcode event names.

## Gotchas

- **gallery-dl exits 0 on errors.** Errors arrive in the JSON as `[-1, {...}]`
  entries, and `parse_listing` raises on them. Always pass `--` before the URL.
- **Flickr's image CDN returns 502 to httpx's default client.** Use
  `download.make_client()`, which sends `User-Agent: flickr-find-me/...`.
- **Only download from `https://*.staticflickr.com`** (`is_flickr_image_url`).
- **OpenCV:** insightface depends on `opencv-python`, which needs X11/GL. An
  override in `pyproject.toml` drops it in favour of `opencv-python-headless`.
  If `cv2` disappears locally after a dependency change, run
  `uv sync --reinstall-package opencv-python-headless`.
- **Face model location:** `FLICKR_FIND_ME_MODELS` sets the model directory,
  which defaults to `~/.insightface`. The Docker image bakes the models into
  `/models`.

## Releasing

Push a tag `vX.Y.Z` (and bump `version` in `pyproject.toml`). The GitHub
workflow runs the tests, then builds and pushes `linux/amd64` and `linux/arm64`
images to `ghcr.io/kaspernissen/flickr-find-me:X.Y.Z` and `:latest`. A plain
push to `main` only runs the tests.

## Commits

Small, conventional messages (`feat:`, `fix:`, `docs:`, `chore:`). No
co-author or "generated by" trailers.
